## 7. 3D ELEMENTS (react-three-fiber, LAZY-LOADED)

Implement exactly these three, each in its own lazily-loaded component (`React.lazy` + `Suspense`, with a lightweight CSS skeleton fallback):

1. **Hero scene** — a floating, slowly rotating low-poly icosahedron/torus-knot cluster with a wireframe + gradient material, 2–3 smaller orbiting shapes, soft ambient + directional lighting. It reacts to mouse movement (parallax rotation, damped with lerp) and to scroll (slight scale/position shift). Use `drei` helpers like `Float` and `Environment` only if they don't hurt load; prefer simple materials.
2. **Skill sphere (desktop only, optional flag)** — a rotating sphere of skill-name labels (HTML via drei `Html` or sprite text) that can be dragged to rotate and slows on hover. Limit to ~25 labels (top skills from the Frontend and Languages groups).
3. **Contact section accent** — a small, low-cost 3D object (e.g. a floating envelope-like or low-poly planet shape) that gently rotates.

3D performance rules (non-negotiable):
- Canvas settings: `dpr={[1, 1.5]}`, `frameloop="demand"` where the scene is static-ish or `"always"` only while the canvas is in the viewport; pause rendering when off-screen using IntersectionObserver.
- Pause rendering when the tab is hidden (`document.visibilityState`).
- Use `useFrame` with delta-based motion, no per-frame object allocation, reuse geometries/materials via `useMemo`.
- Keep polygon counts low (<5k triangles per scene), no heavy textures, no external model files, no HDR files. Generate geometry procedurally.
- Dispose of geometries/materials on unmount.
- Do not mount 3D at all on: devices with `navigator.hardwareConcurrency <= 2`, `prefers-reduced-motion: reduce`, `saveData` enabled, WebGL unsupported, or when Performance mode is on. In those cases render a static CSS gradient/SVG fallback of the same dimensions (no layout shift).
- Wrap each Canvas in an Error Boundary that falls back to the static visual.
- On screens below 768px, render a reduced version (fewer shapes) of the hero scene only; no skill sphere.

## 8. ANIMATION AND INTERACTION SPEC

Use Framer Motion with shared variants in `/src/animations/variants.ts` and shared durations/easings from theme config. Animate ONLY `transform` and `opacity` wherever possible; never animate `width`, `height`, `top`, `left`, or box-shadow blur in loops.

Required effects:
- **Page load:** short staggered hero reveal (name letters or words slide up with mask, then subtitle, buttons, stats). Total under 1.2 s.
- **Scroll reveal:** sections and cards fade-up once using `whileInView` with `viewport={{ once: true, margin: "-80px" }}`.
- **Stat counters:** count up once when visible (requestAnimationFrame-based or Framer `animate`), final values from profile.ts.
- **Timeline:** scroll-linked line draw using `useScroll` + `useTransform` on the experience section.
- **Project cards:** pointer-based 3D tilt (max ~8°) using `useMotionValue`/`useSpring` (no React state updates on mousemove), cursor-following spotlight via CSS variables set from a rAF-throttled handler, smooth lift on hover.
- **Project filter:** `AnimatePresence` + `layout` transitions.
- **Page transitions** between home and project detail: fade + slight slide, 250–350 ms. Restore scroll position when returning to home.
- **Magnetic buttons:** primary CTAs (including "Live demo") subtly pull toward the cursor (desktop pointer only).
- **Navbar:** hides on scroll down, shows on scroll up; background blur increases after scrolling.
- **Micro-interactions:** hover/focus/press states on all interactive elements; focus rings always visible and styled.
- **Theme toggle:** animated icon morph; theme switch uses a short color transition via CSS variables (no full-page flash).
- **Konami-style easter egg is NOT required.** Do not add features beyond this spec.

Reduced motion: if `prefers-reduced-motion: reduce` OR the Performance mode toggle is on, disable parallax, tilt, magnetic effect, custom cursor, smooth scroll, 3D, and looping animations (including the "Live" pulsing dot); keep simple opacity fades only. Implement this through one `useMotionPreference()` hook used everywhere.

## 10. PERFORMANCE ARCHITECTURE (HARD REQUIREMENTS)

Targets on a mid-range phone, production build: Lighthouse Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95; LCP < 2.5 s, CLS < 0.1, INP < 200 ms.

- Route-level code splitting with `React.lazy`; 3D libs (three, r3f, drei) in a separate chunk loaded only when needed and after first paint (use `requestIdleCallback` with timeout fallback).
- Configure Vite `manualChunks` to separate `react`, `framer-motion`, and `three` vendor chunks.
- Import only what is used (named imports from drei and lucide-react; no wildcard imports).
- No layout thrash: no `getBoundingClientRect` in scroll handlers without rAF throttling; use IntersectionObserver instead of scroll listeners wherever possible.
- Memoize expensive components (`React.memo`, `useMemo`, `useCallback`) and keep context values stable; split contexts so a theme change does not re-render everything.
- Pointer-move and scroll handlers: passive listeners, rAF-throttled, and writing to motion values/CSS variables, never to React state.
- Images: all provided images lazy-loaded with explicit width/height or aspect-ratio, `loading="lazy"`, `decoding="async"`, WebP/AVIF where possible. Hero content must never wait on images.
- Do NOT embed the live project sites in iframes anywhere (performance and security). Live demos open only via external links.
- Fonts: preload the two critical font files, `font-display: swap`, subset to Latin.
- Use `will-change` sparingly and only during active animation.
- Avoid heavy blur layers stacked over large areas; limit `backdrop-filter` to navbar and small cards.
- No console errors or warnings in production; no unused dependencies.
